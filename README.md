# agent-skills

A central hub of agent skills for many projects (data engineering, infrastructure, business, and more). Each project loads only the skills it needs.

## Layout

```
skills/<domain>/<skill-name>/   source of truth (agentskills.io format: SKILL.md, references/, scripts/, evals/)
skills/domains.json             domain descriptions
vendor/                         third-party skill repos as pinned git submodules (never edited)
template-skill/                 starting point for a new skill
scripts/                        validate.py, build.py
runtimes/python/loader.py       reference loader for custom agents
plugins/, .claude-plugin/        GENERATED by scripts/build.py
```

Start with [writing-agent-skills](skills/authoring/writing-agent-skills/SKILL.md) and [docs/CONTRIBUTING.md](docs/CONTRIBUTING.md).

## Using skills from another repo

**Claude Code.** Add this repo as a marketplace and install the domains you need.

```
/plugin marketplace add <owner>/agent-skills
/plugin install authoring@agent-skills
```

**Codex.** Not generated yet.

**Custom runtimes** (for example an OpenAI function-calling bot). Pin the hub as a git submodule, copy `runtimes/python/loader.py` into the consumer, and point it at the domain directories you need. `allow` restricts routed skills to the ones you list; always-on skills in those directories always load.

```python
from pathlib import Path
import loader

hub = Path("vendor/agent-skills/skills")
skills = loader.discover([hub / "databricks"], allow={"system-tables-jobs", "system-tables-billing"})
```

If the consumer ships in a container image, copy the same domain directories into the image at build time. Use `loader.build_menu`, `system_prompt` and `TOOL_SCHEMAS` in one of three modes: `router`, `tool` or `eager`. See the loader's docstring.

## Development

```bash
git clone --recurse-submodules <repo-url>
uv sync
uv run python scripts/validate.py
uv run python scripts/build.py          # regenerate; CI runs build.py --check
```
